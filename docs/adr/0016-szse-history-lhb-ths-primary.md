# ADR 0016：深圳历史龙虎榜 basic 同花顺主采与官方保留

2026-10-28，issue #128（父需求 #125）；替代 ADR 0015 对深圳历史 `lhb_basic` 的主源与默认启用决策，官方恢复后的补充对拍由 #130 跟踪。

## Context

- 深交所 ShowReport 在历史回溯中反复出现连接级失败：多日回溯失败、90 日任务再次中止，冷却后单线程 5 秒间隔探测仍为 0/3 成功，更换 TLS 客户端也收到空响应。单页重试只能处理瞬时故障，不能满足历史任务对持续可用性的要求。
- 同花顺历史日期页已具备按交易日提供 `lhb_basic` 的实现与校验，但 ADR 0015 只允许显式后备，并要求深交所恢复且完成真实对拍后才允许默认启用；这一前提使已验证的可用性替代方案被不可用的官方源长期阻塞。
- 采集优先级与数据权威性是不同决策：同花顺适合承担稳定采集，已取得的官方完整数据仍具有校验与留存价值。

## Decision

- 仅调整深圳历史回溯及统计前置 staging 的 `lhb_basic`：同花顺为主采源，深交所官方用于失败补缺、后续校验与已有数据保留。单日、`close`、`--check` 和沪市、北交所现有主源行为不变。
- 深圳默认请求链为同花顺 → 深交所官方。同花顺成功即完成，不默认重复请求官方；同花顺失败才尝试官方，双源失败才保留旧数据并报错。同花顺通过日期、业务键、金额一致性和目标证券校验后即为完整输入，官方缺失不再产生该日 `partial_error`。
- 已确认的完整官方日默认保留。依据成功采集台账、实际 basic 行及来源明细识别官方数据；无深圳后备标记才视为官方。来源无法确认的历史行可按当前主源刷新并记录，不新增 basic 来源列。历史 `lhb --force` 显式要求整窗重抓时才允许替换已保留官方日。
- staging 优先复用库内完整 basic，仅补缺失或来源无法确认的日期，不写窗外业务表；statistic 仍按既有近 60 日历日公式重算。
- `--fallback ths` 保留给沪市、北交所官方失败时的显式补缺；深圳无需该参数。
- 同花顺每个历史日期最多一次请求、日期间 20 秒退避、封禁停止且无同源自动重试；未实测的 TPS、并发和最小安全间隔标为待验证。实际主源、后备、市场及行数继续进入结构化响应和采集台账。
- #128 以解析、编排、来源、旧数据保护和回归测试验收，不再等待官方恢复。#130 在官方恢复后保存真实样本并补充对拍；发现的阻断性数据问题另建缺陷并评估存量数据。

## Consequences

- 深交所持续不可用不再阻塞深圳历史回溯，但同花顺成为该路径的可用性关键源，其低频纪律、HTML 契约和金额校验必须继续严格执行。
- 官方数据保留依赖采集台账的来源证据；来源不明的存量行不冒充官方，可按新主源刷新并留下记录。
- ADR 0015 保留默认关闭阶段的历史决策，其实施机制继续有效；凡与本 ADR 的深圳主源、官方保留、staging 复用和默认启用规则冲突之处，以本 ADR 为准。
