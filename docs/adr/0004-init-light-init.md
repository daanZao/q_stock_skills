# init 轻量初始化：建表 + 三部分数据，全量回溯显式开启

`init_database` 默认做轻量初始化：幂等建表之外，抓取**股票清单**、**全市场快照**、**主要指数日线**（上证/深成/创业板/沪深300/上证50/中证500/科创50 的全历史日线）。三部分独立 fallback 重试、独立成败报告：单部分失败不拖垮其他，输出 `parts` 逐项报告行数与实际数据源，仅全部数据部分失败才整体 `error`（沿用盘面快照的 section 约定）。全市场个股历史日线回溯（数千只 × 全历史）由 `backfill_history=True` 显式开启，绝不默认执行；复用日线头尾自愈（`ensure_coverage`），单股失败不中断，失败清单在 `parts.backfill.failed` 报告。

关键的结构决策：

- **股票清单独立表 `stock_list`**（主键 `stock_code`）：它是全量回溯与后续能力的标的来源，与快照表解耦；适配层新增专用 `fetch_stock_list` 协议。efinance 无专用清单接口，退化为全市场快照取代码/名称两列。
- **指数日线独立表 `index_daily`**：指数代码与个股代码冲突（`000001` 既是上证指数又是平安银行），无法复用 `stock_daily`；指数无复权概念，表不带 `adj` 列，业务键 `(index_code, trade_date)`。适配层新增 `fetch_index_daily` 协议（不带复权参数）；efinance 无干净的指数历史接口，明确拒绝。

理由：轻量初始化让"装好即用"——一次调用后股票清单、当日盘面、指数背景均已落库；重操作藏在显式参数后面，避免误触发的长时间全量抓取。各部分按业务键 upsert，重复调用幂等（无报错、无重复行）。

## Consequences

- 三部分成败相互独立，调用方需读 `parts`/`failed_parts` 判断哪些部分需要重试；重试方式就是再调一次（幂等）。
- 全量回溯以 `stock_list` 为标的来源，清单缺失的股票不会被回溯；回溯固定前复权（`qfq`）。
- 指数与个股日线分表存储，查询方需按主体类型选表，不能用一张表查全部。
