# ADR 0021：raw/qfq 双日线与前复权事件重锚

2026-11-20，spec #206；取代 ADR 0018 的 B0/F/hfq/state 复权模型。

## Context

ADR 0018 以 raw、窗口基线 B0、累计因子、物化 hfq 和每股状态派生 qfq。该模型把完整性证明绑定到窗口外基线和全历史事件证据，基线不可信时会阻断派生；窗口重锚还可能使既有 qfq 缩放错误。legacy 与影子模型的切读、回填和八项迁移验收进一步放大了复杂度，#158 下辖任务体系已失去继续实施的有效前提。

新设计比较了三条路线：继续 raw+B 读时派生、每次事件重抓单票全历史 qfq、初始化上游 qfq 后只做事件驱动重锚。第一条仍依赖完整因子与基线语义，第二条把每次事件的成本交给上游分页和日预算。第三条利用“最新锚下当日 qfq=raw”和“新事件只需缩放事件日前历史”的性质，取消 B0/hfq 中间链，同时把全历史上游请求主要限制在初始化和人工恢复。

本 ADR 记录已经接受的目标架构，不代表新表已建、消费方已迁移或生产已切读。现行实现仍按既有代码运行，直到 #206 的下游任务分别完成。

## Decision

### 1. raw 与 qfq 是两个独立口径

- 保留 `stock_daily_raw` 的现有历史范围、Universe 和采集语义；raw 不再作为本地派生 qfq 的底座。
- 新建 `stock_daily_qfq`，初始化直接采集 baostock `adjustflag=2` 的 2005 年至最新交易日日线。2005 年以前的除权影响已包含在上游 qfq 中，本地不还原。
- 新模型不提供 hfq，不建立或消费 B0、归一累计因子 F、hfq 中间表和旧 `factor_state`。
- qfq 是以当前最新除权事实为锚的可变读模型，不是 point-in-time 历史快照。
- 两张价格表保留官方日线核心字段；成交额仍为万元、成交量仍为股，本地重锚不改变非价格字段的单位或来源。

### 2. 初始化与日常追加分离

- 全量初始化前先执行约 20 只代表股票样本，记录接口、窗口、股票范围、分页、协议动作数、耗时、成功率、空值和精度；单次样本不外推长期 TPS 或全市场工期。
- 初始化和人工刷新按股票取得完整结果后写入，分页失败不得留下半段单票历史。初始化和续跑沿用 baostock 显式租约、串行、至少 1.5 秒请求间隔和日预算。
- 每日 raw 按现有权威逻辑入库，同一最新行以 `raw_identity` 写入 qfq 表；最新锚下 `qfq=raw`，不逐票请求全市场当日 qfq。

### 3. 除权事件只重锚事件日前历史

- `query_daily_adjust_factor(T)` 是 T 日全市场事件集；成功空结果才表示无事件，失败不得记成无事件。
- 事件股票的本次因子由单票 `query_adjust_factor()` 返回的相邻累计值计算：`f_T=B_prev/B_cur`。累计 B 只取 `backAdjustFactor`，`adjustFacto(r)` 不参与业务派生。
- 初始化不补历史因子。第一次新事件按需取得单票因子历史，之后只维护新模型运行后的前向事件因子。
- T 日重锚只将 `date<T` 的 OHLC/preclose 乘以 `f_T`；T 日及之后的行完全不变，成交量、成交额、换手率、涨跌幅、交易状态和 ST 标志也不变。
- 历史重锚与对应 pending 清除在同一事务中完成，保证每个事件至多应用一次；该事务不回滚或重写 T 日及之后的新行。

### 4. 来源、锚日期和 pending 是公开语义

`stock_daily_qfq` 在价格字段之外增加以下行级元数据：

- `value_origin`：`upstream_qfq` 表示上游直接 qfq，`raw_identity` 表示最新 raw 恒等写入，`local_reanchor` 表示事件导致的本地乘算。它只描述价格字段，不把整行非价格字段标为本地计算。
- `qfq_anchor_date`：初始化行为实际数据截止交易日，日常新增行为空，事件重锚后事件日前历史行更新为该事件日。它不是“该日期一定发生除权”的声明。
- `adjustment_status`：正常为空；全日事件集未核验时为 `factor_unverified`，已确认事件但历史重锚未完成为 `reanchor_pending`。

全日因子失败和单票重锚失败可以连续发生，系统不假设最多一个 pending。重查待核验日期时，无事件则清除状态；有事件则进入重锚。多个 pending 按事件日期顺序补偿，新日线仍可持续追加。

pending 表示事件日前历史尚未完成重锚，不表示 T 日及之后的新行错误。MCP 查询必须按股票检查全部未解决状态，而非只检查本次返回行；close 汇总数量、股票、事件日期和原因。

### 5. 对账与全量恢复保留人工判断

- 事件处理时抽取最早存储日、事件前一交易日和固定历史抽样日，与上游最新 qfq 对账；抽样失败记未校验，不当作通过。
- 本地重锚允许与上游四位小数结果存在尾差，验收容差由真实样本形成报告后交用户确认，不预写未经验证的数值。
- 超差、事件关系无法证明或长期 pending 只报告，不按年龄、数量或超差自动全量重抓。
- 人工单票刷新覆盖 2005 年至最新交易日；成功后恢复 `upstream_qfq`、统一锚日期并清除该股票全部 pending。
- 初始化、断点续跑和人工刷新的功能属于 #206；正式 CLI 名称、参数、工件和操作手册另立 issue。

### 6. 公共查询与旧模型退出

- 新增固定口径 `query_daily_qfq`、`query_daily_raw`，均不接受 `adj`。qfq 响应披露行级来源、锚日期和股票级 pending；raw 响应不伪造复权覆盖。
- 现役 skills、indicator-tools、强势股、申万聚合和覆盖核验迁到新的价格读取接缝后，删除旧统一 `query_daily`，不保留隐藏转发或 none/hfq 兼容口径。
- close 是否承接 morning 的采集职责由 #205 独立澄清；本 ADR 只确定 close 披露 pending，不预设调度迁移结论。
- 新模型完成回填、消费迁移和切读验收后，才以可重复、可还原的数据库工件物理删除 legacy 日线、hfq 和旧状态表。代码完成、回填完成、硬验收和切读分别验收。
- #158 及下辖旧模型任务保留审计记录并标为废弃，链接 #206；不得继续沿用旧 B0 验收公式或把旧开发演练当作新模型生产证据。

## Considered Options

- **raw+B 读时派生 qfq/hfq**：拒绝。仍要求完整因子和基线语义，且保留 hfq/state 与横截面派生复杂度。
- **每次事件重抓单票全历史 qfq**：拒绝作为默认路径。它把常规事件处理变成上游长历史分页请求，扩大日预算和失败面；保留为人工恢复能力。
- **初始化上游 qfq + 本地事件重锚**：采用。取消 B0/hfq，常规事件只产生一次单票因子查询和本地历史更新；代价是接受可变历史、尾差和显式 pending。
- **失败即禁止读取或回滚当日行**：未采用。新行持续可用，历史混合锚必须显式披露并等待补偿，不静默伪装成完整。
- **自动超期/超差全量刷新**：未采用。连续上游异常和抽样差异需要人工判断，避免自动放大上游请求。

## Consequences

- 同一历史交易日的 qfq 会随新事件改变，严格历史时点回测需要另建版本化快照，不属于本模型。
- 本地乘算可能与上游重抓结果存在尾差；行级来源、抽样对账和人工全量刷新是必要配套，不能省略。
- pending 期间同一只股票可能同时包含尚未重锚的历史和正确的新行，所有消费方必须保留警告，不得仅凭有行判 complete。
- 旧 `QSTOCK_PRICE_SOURCE`、B0 回填、hfq/state 验收和修复回滚不再是新模型的设计依据；其物理退役必须晚于新模型切读验收。
- 数据库字典、项目知识图、MCP 描述和 skills 文档随对应 schema、入口和消费迁移同步更新，不把目标架构提前写成已交付现状。
