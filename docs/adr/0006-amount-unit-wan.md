# 金额单位统一规约为万元

库内所有金额列（成交额、市值、龙虎榜买卖净额等）统一以**万元**存储。上游各源口径不一（东财原始列为元，营业部榜为 "X亿"/"X万"/无单位中文字符串），历史上按上游原值直存导致同库单位分裂，跨表资金计算极易出错。

换算收敛在适配器映射层单点完成：东财元值经 `_wan()`（÷1e4），中文金额字符串经 `_money_cn()`（"X亿"×1e4、"X万"原值、无单位纯数字按万元计——上游实测其量级与"万"档自洽，属推断口径，见 `_eastmoney.py` 注释）。基本面透传（proxy 面）不规格化、保持上游原样，不在本规约范围。

存量数据不做迁移：库内行情表全部清空后按新口径重新抓取（用户确认无外部消费方、数据可弃）。`conclusions`/`news_items` 非行情表且无再生成路径，保留——其中历史结论 payload 与已落盘报告中的金额为旧元口径，属历史文档，不回改。

## Consequences

- `query_daily`/`query_snapshot`/`query_board_data` 输出的金额字段数值较旧口径缩小 1e4 倍——ADR 0001 的输出结构契约不变，但金额语义变更，消费方（各 skill 报告的展示换算）按万元起算。
- 比值类指标（vol_price 的 amount_chg、corr）不受单位影响。
- 新增金额列时默认万元口径，换算必须发生在适配器映射层，工具层与 repository 不再处理单位。
- 营业部榜（lhb_yyb_*）上游不提供的列（卖出/净额等）恒为 null，不伪造；`lhb_yyb_most.buy_amount` 的上游口径为"合计动用资金"（买+卖合计），非纯买入。
