## 实体清单

### MCP server 入口与公共层

- **`server.py`**：stdio MCP server，18 个工具只做薄包装，核心逻辑全在 `tools_*` 模块（`src/qstock_mcp/server.py:1-5`）；数据库连接按工具调用建立，启动不依赖 PG 可达（`server.py:4`）。入口 `qstock-mcp = qstock_mcp.server:main`（`pyproject.toml:17`）。
- **`output.py`**：统一错误输出契约——`status:"error"` + 工具名 + 参数回显 + 原因，工具层不抛异常（`output.py:4-6`、`db.py:31-41`）。
- **`dates.py`**：日期统一 `yyyymmdd`（接受 `yyyy-mm-dd`）；`days` 按交易日≈自然日 7/5 加 buffer 换算区间，宁多抓不少抓，换算落点是非交易日时 start 向前对齐到最近交易日（周末 + `_MARKET_CLOSURES` 已知休市表，issue #51）（`dates.py:62-73`、`dates.py:75-97`）。`is_trading_time`/`today_str`：交易时段判定（交易日 09:30–15:00 东八区），盘中禁写防线（issue #78）的判定内核，时钟可注入。
- **`db.py`**：连接串只从 `PG_DSN` 环境变量读（ADR 0002）；`ensure_schema` 幂等执行 `sql/*.sql` 全部 DDL（`db.py:21-28`、`db.py:44-54`）。

### 五个能力面（核心层 = 第一测试接缝，测试注入 fake 适配器 + 真实 PG 测试库）

- **init — `tools_init.py`**：轻量初始化 = 幂等建表 + 股票清单 + 全市场快照 + 7 个主要指数全历史日线，三部分独立成败，输出 `parts`/`failed_parts`，仅全败才整体 `error`（`tools_init.py:1-13`、`tools_init.py:168-219`、ADR 0004）。`backfill_history=True` 显式开启全量回溯：以 `stock_list` 为标的来源、固定 qfq、复用日线头尾自愈、单股失败不中断（`tools_init.py:117-165`）；个股日线回溯走 `default_daily_adapters`（腾讯→新浪→baostock，issue #112；腾讯 640 根/请求，全历史逐股约 19 次请求，重操作）；全市场快照部分走 `default_snapshot_adapters`（issue #116，腾讯批量报价→腾讯 rank→新浪，注入适配器时沿用同一组 fake）。`query_index_daily` 为 index_daily 纯读查询（issue #33/T1）：index_code 限 7 个主要指数（白名单校验，未知代码 error 并列可选项），日期闭区间 + limit 取最近 N 行（缺省 120）升序返回，空结果 `count:0` 非错误，不触发补抓（`tools_init.py:224-284`）。**能力面归统一查询**（`CONTEXT.md`），实现暂驻 tools_init：与写入方 `_init_index_daily` 同模块共享 `MAJOR_INDICES` 白名单/指数名，迁往 tools_daily 会与 tools_init→tools_daily 的 `ensure_coverage` 依赖成环。`import_board_classification`（issue #73，spec #70）：成分字典显式导入入口，以文件为准清空重载某 source_system（事务内删除后重载、陈旧行不残留、重复执行幂等），本期仅 'sw'（申万 .xls，解析在 `_sw_classify.py` 纯函数、xlrd 懒加载，股票代码补零 6 位）；采集台账挂接点 `_ingest_ledger_hook` 已预留（台账表 #71 落地后接线）。`import_sw_industry_meta`（issue #74）：申万行业名称表种子导入，仓库内置 CSV 种子（`data/sw_industry_meta.csv`，加载在 `_sw_classify.load_sw_industry_meta_seed`）按 industry_code 幂等 upsert，只动 meta 不碰成分变更史；来源验证与合并规则见 `docs/research/2026-10-17-sw-industry-meta-sources.md`。`refresh_sw_dict`（issue #118，spec #111）：成分字典在线刷新——申万官网分类 xls 直链下载（`SwBoardsAdapter.fetch_sw_class_file`）→ 临时文件 → 复用 `import_board_classification` 事务清空重载 'sw' 体系（含北交所归属），把 issue #73 的手工文件导入升级为在线刷新（`qstock-scheduler sw-dict`），重复执行幂等。
- **fetch/query 日线 — `tools_daily.py`**：`ensure_coverage` 只补请求区间头尾缺口（中段缺口视为停牌），是全量回溯与查询自愈共用的公共能力（`tools_daily.py:24-48`）；个股日线 fallback 链为 **腾讯 → 新浪 → baostock**（issue #112，`default_daily_adapters`；东财日线退役，akshare `fetch_daily` 显式 `unsupported`），北交所旧码 43x/83x/87x 经 `adapters/_bse_codes.py` 按官方 248 条对照表归一化到 920 新码；三源对拍在独立模块 `daily_parity.py`（`compare_daily_sources`）：逐源直取同日 bar 做字段级对拍、不落库，hfq 只比量/额/换手率（CLI `daily --check`）。`fetch_daily` 与 `query_daily` 共用 `_run` 骨架（参数解析→连接→自愈），前者报告 upsert 行数，后者返回完整区间行（`tools_daily.py:67-147`）。盘中禁写（issue #78）：交易时段内当日行不落库（defer 机制，fetch 报告 deferred 计数、query 把盘中行随响应返回并带 note）。停牌标注（issue #80）：`query_daily` 每行带 `tradestatus`（baostock 权威，其余源 null）+ `suspended`/`suspended_basis`（tradestatus 优先，OHLC 全等且 volume/change_percent 为 null 的启发式兜底），停牌占位行与数据缺失行由此可区分。
- **fetch/query 快照 — `tools_snapshot.py`**：全市场快照单次调用约 5000+ 只；fallback 链（issue #116，spec #111）为 **腾讯批量报价（qt.gtimg.cn，主源）→ 腾讯 rank 榜单 → 新浪直连**，东财链路退出快照承载，生产默认 `default_snapshot_adapters`（`adapters/__init__.py`）；主源 18 字段全覆盖、时间戳含日期可过 #78 带参防线，需股票清单驱动（默认提供者 `adapters/_snapshot_codes.py`：akshare 交易所官网清单 → 库内 stock_list 兜底，双路皆失败转 rank）；rank 免清单但缺 OHLC/pre_close（涨跌家数口径改由 change_percent/zdf 判定），新浪直连绕过 akshare 封装（其丢 7 字段）且 ticktime 无日期。交易日优先级：API 报告 > 传入参数 > 当天，但传入日期与 API 生效日期不符（含 API 未报告）即 error + `detail:date_mismatch` 零落库（issue #78 防线，"API 优先"仅限不传参）（`tools_snapshot.py:80-85`）。三态错误契约首个落地（issue #46，ADR 0007）：全源失败按逐源 `failure_kind` 聚合 `error_kind`——任一抓取源连接级故障即 `upstream_unreachable`（带 `retry_advice`），否则 `fetch_failed`；by-design 不支持的源不参与判定；上游正常响应空结果为 `no_data_for_date`（status ok + `empty_kind` + note，非失败）。`query_snapshot` 服务端聚合与排序取前 N（issue #48）：`aggregate=breadth,amount` 聚合模式返回上涨/下跌/平盘家数（有昨收按最新价 vs 昨收判定，昨收缺失改由 change_percent 判定，issue #116；含沪/深/北分市场口径——代码前缀 6 沪 / 4·8·9 北，同 `is_bse_code` / 其余深）与成交额合计（万元，ADR 0006），不返回行，环比由调用方对当日/前一日各调一次完成；`order_by`（快照列白名单）+ `limit=N` 排序取前 N（`order` asc/desc 缺省 desc），行字段与整表查询一致不裁剪列；聚合与 ORDER BY/LIMIT 均下推 SQL，新参数与 `trade_date`/`stock_code` 正交、不传行为不变；明确不做通用 offset 分页（防翻页拼全表）。三源字段级对拍在独立模块 `snapshot_parity.py`（`compare_snapshot_sources`）：逐源直取同日快照比对、不落库，结构性缺项跳过（rank 缺 OHLC/pre_close、新浪缺振幅/量比），差异含已知 PE 口径切换信号（CLI `snapshot --check`）。

## 关键流程

- **查询自愈（头尾缺口）**：`query_daily`/`fetch_daily` → `resolve_range` 解析区间 → `select_dates` 取库内已有日期 → `head_tail_gaps` 算头尾分段（最多两段，中段缺口=停牌）→ 逐段 `fetch_with_fallback` → `upsert_daily` → `select_daily` 返回完整区间，自愈分段在输出 `healed`/`segments` 中报告（`tools_daily.py:67-99`、`gaps.py:10-21`）。
- **fallback 与重试**：每种抓取（日线/快照/五 section/基本面/清单/指数日线）各有一个 `fetch_*_with_fallback`，共享同一 `_with_fallback` 内核：按链顺序尝试、每源最多 3 次尝试（unsupported 单次即弃，重试间退避 0.5/1/2s 抖动，issue #87）、空结果即成功、全失败抛 `AllSourcesFailed`（`fetch_chain.py:105-262`）。例外：`fetch_index_spot_with_fallback`（单 code 指数补漏，issue #49）空结果（源口径不含该指数，failure_kind "empty"）不视为成功、立即转下一源不重试，error_kind 用 `aggregate_patch_error_kind` 判定；`empty` 作为补漏路径专用第四个逐源 failure_kind 的正式口径（语义与边界）见 ADR 0007 补记。
- **section 级独立成败**：`fetch_board_snapshot` 与 `init_database` 同构——逐项独立 fallback、逐项成败进 `sections`/`parts`，仅全部失败才整体 `error`；board 侧另有核心 section fail-fast（issue #47）：核心 section 因 upstream_unreachable 失败即整体 error 并携带 per-section 明细，中途失败不回滚、按 trade_date 幂等、可用 sections 参数分段重试（`tools_board.py:132-238`、`tools_init.py:192-219`）。整把重试方式就是再调一次（幂等，ADR 0004）。
- **结论 upsert**：业务键在 schema 层钉死；CTE 预查判定 `inserted/updated`；payload 不校验，结论类型（`daily_review.close`、`sepa.full` 等）的字段约定由各 skill 文档承载（ADR 0003）。
- **mx 调用与资讯沉淀**：`mx_query`/`mx_search` 走 `_mx_exchange` 骨架——配额先检（触顶不调上游直接 error）→ 调上游 → 触达即记账 → 业务码判定（code!=0 走 error 契约）；`mx_search` 成功即按 news_code 去重并业务键 upsert `news_items`；`query_news` 纯读库（倒序 + limit），不经骨架、不计配额（`tools_mx.py:60-116`、`tools_mx.py:142-230`）。
- **skill 间数据流**：`query_daily` JSON（跨仓库稳定契约，ADR 0001）→ indicator-tools stdin → 指标 JSON → 方法论 skill（sepa）判断 → `save_conclusion`；编排 skill 同样经管道消费指标（daily-review 用 corr/vol_price/deviation，limit-up-analysis 用 promote，专用输入按各自契约组装）；daily-review 的涨停/连板章节取自 limit-up-analysis 落库的 `limit_up.close` 结论。
