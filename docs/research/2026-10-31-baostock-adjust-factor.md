## 0. 结论速览

一句话：**可以作交叉校验源，但定位是"事件表/日期对账源"，不是"因子数值的独立真值源"。**
最划算的用法是每交易日 1 次 `query_daily_adjust_factor(date)` 拉全市场事件表，与
preclose 推导出的"异常日集合"做召回/误报对账；单票 `query_adjust_factor` 用于长历史
累积因子与事件清单。

## 1. 接口事实（源码级，非二手文档）

`query_adjust_factor` 与 `query_daily_adjust_factor` 均由 `baostock/__init__.py:25-26`
导出，实现在 `baostock/evaluation/season_index.py`。

### 1.1 `query_adjust_factor(code, start_date=None, end_date=None)`

- 源码：`evaluation/season_index.py:107-183`。`start_date` 缺省 `2015-01-01`
  （`contants.py:123` 的 `DEFAULT_START_DATE`），`end_date` 缺省为当天。
- 参数是**除权除息日区间**（docstring 原文"起始除权除息日期"），不是交易日区间：
  传 `2023-01-01..2024-12-31` 只回 2023/2024 两个事件行（§3.3），窗口外的事件被过滤，
  因此**窗口内首个事件没有前值、算不出 f**。
- 返回字段（实测 `rs.fields`）：
  `code, dividOperateDate, foreAdjustFactor, backAdjustFactor, adjustFactor`。
- 分页：`PER_PAGE_COUNT=2000`（`contants.py:187`），`ResultData.next()` 会在满页时
  自动发后续页请求（`data/resultset.py:54-110`）。单票事件数远小于 2000，
  本轮 6 次 `query_adjust_factor` 调用均为 1 页。
- 对退市代码同样返回 `error_code=0` 与历史行（§6.4），不报错、不空返回。

### 1.2 `query_daily_adjust_factor(date)` —— 被低估的那个

- 源码：`evaluation/season_index.py:185-245`。**入参只有一个日期**，`per_page_count`
  写死 20000 且不翻页（`data/resultset.py:67-71`：`len(data) > 2000` 直接返回 False）。
- 返回字段同上五列。实测 `date=2026-10-16` 返回 **48 行**，且 `dividOperateDate` 全为
  `2026-10-16` → 它是**某一个除权日的全市场事件表**，不是"当天全市场因子快照"。
- 含义：**1 次请求 = 当天全市场除权事件清单**。做"事件对账"的成本是每交易日 1 次，
  不是每票 1 次。

### 1.3 客户端硬约束：没有读超时

`baostock/util/socketutil.py:55` 的 `send_msg` 是 `while True: recv(8192)`（循环在 `:67-68`）直到读到
`<![CDATA[]]>\n`，**全文件没有任何 `settimeout`**（`grep timeout util/ common/` 无命中）。
后果：上游不返回就永久阻塞。本轮第 8 次请求（`query_daily_history_k_AStock(2026-10-16)`，
全市场 5,226 行）**挂起 >15 分钟后只能杀进程**（§2 偏差披露）。生产上若要用这个接口，
必须在外层加超时（见 §8）。

## 2. 实测方法与偏差披露（数据源纪律）

- **串行、低频**：单进程顺序调用，相邻两次 `sleep(1.5s)`（用一次性进程时由
  `login()` 后统一 sleep 保证）；无并发、无重试。
- **样本**：
  - 事件级对比 3 只：`sh.688300`（2026-10-16 10 送 3，已知锚点）、`sh.600519`
    （沪市现金分红，2021–2026 共 11 个事件行）、`sz.000001`（9 个事件行）。
  - 边界 4 只：`sz.000016`（`*ST康佳A`，2026-09-04 起停牌，兼 ST 样本）、
    `sh.600200`（`退市苏吴`，2025-12-29 后退市）、`sz.301569`（2026-10-15 上市新股，
    数据取自 PG 既有 `adj='none'` 行，未额外请求）、688300 兼作锚点。
  - 全市场：2026-10-16 的因子事件表 vs PG 里同日 5,226 只 A 股的 `adj='none'` 行。
- **偏差披露 1（必须记账）**：第 8 次请求挂死，占用一次请求额度且无数据。它是
  `query_daily_history_k_AStock` 全市场一把抓，**本次样本不能推断该接口整体不可用**
  （项目次晨批日常在用），但坐实了"客户端无超时、必须外部兜底"。
- **偏差披露 2（方法替代）**：因为上述挂起，本轮**没有拿到 2026-10-16 的全市场
  `preclose` 原始列**。全市场那一节的 preclose 是用 PG `adj='none'` 的
  `close` 与 `change_percent` 反解出来的（`preclose = close/(1+pctChg/100)`）。
  这两列本就来自 baostock 一把抓（上一票已抽验 65/65 逐值一致），且 `pctChg` 存 4 位小数
  → preclose 反解相对误差 ~1e-6，与直接读 `preclose` 同级。3 只核心票的事件对比
  **用的是原始 `preclose` 列**，不受此影响。
- **偏差披露 3（执行失误）**：第一次跑脚本时把内部参数 `_api` 误传给了 baostock 函数，
  6 次调用全部在 Python 签名绑定阶段抛 `TypeError`，**未发出任何 socket 数据**
  （0 上游请求），已在本地修正后重跑。
- 本次为**收盘后的静态历史数据**，非盘中。结论只代表当次样本，不外推长期可用性。

## 3. 字段语义与方向

### 3.1 `backAdjustFactor` = 累积后复权因子

三只票全部满足：单调不减、首行已含该次事件的影响、末行是"截至最后一次事件"的累积值。
例如 688300 从 1.015846（2021-06-24）单调升到 3.855379（2026-10-16）。

事件日价格因子就是相邻两行的比值：

```
f_event = backAdjustFactor(prev_event) / backAdjustFactor(this_event)
```

- 688300 2026-10-16（10 送 3）：`2.965589 / 3.855379 = 0.76920816`（精确 1/1.3 = 0.76923077）。
- 688300 2025-05-29：`2.251720 / 2.956739 = 0.76155521`，倒数 `1.3131024`；上一票 #141 用
  腾讯 qfq/day 平台法得 `1.313226`，两者相对差 **9.4e-05**——两个独立上游在同一事件上
  一致到 1e-4，这是跨源互证。

### 3.2 `foreAdjustFactor` = 前复权乘数（锚在"最近一次事件"）

实测关系（25 个事件全部成立）：

```
foreAdjustFactor(i) = backAdjustFactor(i) / backAdjustFactor(最近一次事件)
```

- 三只票的末次事件行 `fore` 都恰好是 `1.000000`（688300 2026-10-16、600519 2026-06-26、
  000001 2026-09-24）；退市样本 600200 的末次事件（2018-06-15）也是 `1.000000`。
- 语义：`前复权价(t) = 原始价(t) × fore(该 t 所属区间的事件)`，区间 = `[事件日, 下一事件日)`。
  这与 preclose 的关系正好吻合：`preclose(D) = close(D-1) × fore(prev)/fore(D)`。
- **`fore` 是"到最近一次事件为止"的锚，会随新事件前移**，所以不能跨日缓存绝对值；
  但**比值永远稳定**，交叉校验一律用比值。

### 3.3 窗口不变性（正面对比腾讯）

同一票两种窗口各请求一次：

| 窗口 | fore(2023-06-15) | back(2023-06-15) | fore(2024-06-06) | back(2024-06-06) |
| --- | --- | --- | --- | --- |
| `2021-01-01..2026-10-31` | 0.578173 | 2.229076 | 0.584046 | 2.251720 |
| `2023-01-01..2024-12-31` | **0.578173** | **2.229076** | **0.584046** | **2.251720** |

逐字相同。若 `fore` 锚在"查询窗口内最后一个事件"，第二种窗口下 `fore(2024-06-06)` 应为 1.0，
实测不是 → **锚在全局最近事件，与请求窗口无关**。这是它比腾讯 qfq 更适合做长期因子的地方
（腾讯以窗口末行为锚，#141 §5 结论 (b)）。

### 3.4 `adjustFactor` 是脏的，不要用

3 只核心票共 28 个事件行，其中 27 行 `adjustFactor == backAdjustFactor`，唯一例外：

```
sh.600519,2023-06-30, fore=0.898366, back=6.889798, adjustFactor=0.988591
```

`0.988591 = 6.889798/6.969311`，即**下一次事件（2023-12-20）的因子**——这一行有前视污染。
它恰好是一个"重复行"（§6.5）。结论：**只用 `fore`/`back` 的比值，忽略 `adjustFactor`。**

### 4.2 精度来源：`preclose` 只有两位小数

4,230 行 `preclose`/`close` 全部精确落在 1 分钱网格上（`|x*100 - round(x*100)| < 3e-11`，
纯浮点噪声）。所以：

```
f 的单日分辨率 ≈ 0.005 / preclose
  11 元票 ≈ 4.4e-4；100 元票 ≈ 5e-5；1000 元票 ≈ 5e-6
```

**这一段修正 issue 背景里的一句话。** issue 写"preclose(D)/close(D-1) 精确等于 f（688300
2026-10-16 的 10 送 3：0.769231 = 1/1.3，误差 <1e-6）"。实测单日比是
`104.62/136.01 = 0.76920815`，与 1/1.3 的相对差是 **-2.94e-05**，不是 1e-6。原因很直接：
`136.01/1.3 = 104.623077`，两位小数只能记成 `104.62`，反算就带 2.9e-5 误差。
"1e-6"只在**平台法**（除权前多日比值的中位数）下成立——与上一票 #141 §4.1 的
`单日法 0.769208 / 平台法 0.769231` 完全吻合。本报告据此把两种口径分开写。

### 4.3 为什么这**不是**独立校验（本轮最重要的判断）

688300 的 10 送 3，`backAdjustFactor` 比值 = `3.855379/2.965589` = **1.3000382**，
不是精确的 1.3，相对差 **+2.94e-05**。而这个偏差**恰好**等于
`round(136.01/1.3, 2)/136.01 = 104.62/136.01` 的倒数：

```
104.62/136.01        = 0.76920815   ← preclose 推导
2.965589/3.855379    = 0.76920816   ← 因子表推导
1/1.3                = 0.76923077   ← 精确理论值
```

即 **baostock 的累积因子是从两位小数价格递推出来的**，与 `preclose/close(D-1)` 同源同舍入。
两者一致到 1e-6 是"同一舍入误差的两种写法"，不是"两条独立证据互相印证"。

所以：**因子表能校验的不是"因子数值对不对"，而是"哪一天发生了事件、有没有漏事件"。**
`dividOperateDate` 来自交易所除权除息日，这部分才是独立信息。数值上二者精度同级
（受 1 分钱价格量化限制），谁也不是谁的真值。

## 5. 全市场覆盖率（2026-10-16）

1 次 `query_daily_adjust_factor(2026-10-16)` 返回 **48 行**，`dividOperateDate` 全为当天。
与 PG 里 5,226 只 A 股的 `adj='none'` 行对账（preclose 由 `close`/`pctChg` 反解，见 §2）：

| 指标 | 数值 |
| --- | --- |
| 因子表事件行 | 48（45 只 A 股 + 3 只 ETF/基金：515180、530880、563660） |
| DB 有配对行的 | 45（3 只 ETF 不在 A 股日线口径内） |
| preclose 推导检出的事件票（`abs(f-1) > 1e-4`） | 45 |
| **因子表命中** | **45/45** |
| **漏报（推导有、因子表无）** | **0** |
| 误报（因子表有、推导 f≈1 的 A 股） | 0 |

- 召回 **100%**、误报 **0**（当日样本）。45 个事件的 `f_implied` 分布从 0.689755
  （一只 10 送 4.5 的送转，0.689655 = 1/1.45）到 0.998784（小额现金分红），连续覆盖。
- 688300 的 `f_implied = 0.76920804`，与因子表 `0.76920816` 相对差 1.2e-07。
- 口径差异要记住：**因子表含 ETF（3/48），`query_daily_history_k_AStock` 不含**。
  做集合对账必须先按代码前缀过滤，否则会把这 3 只当"误报"。
- 检出阈值 1e-4 意味着**小于约 0.01% 的因子无法从 pctChg 侧检出**，这类事件只会以
  "因子表有行、推导无异常"的形式出现；本轮样本 0 例（最小事件 0.998784）。

## 6. 边界

### 6.1 停牌日：`preclose` = 最后成交价，f ≡ 1

`sz.000016`（`*ST康佳A`，`isST=1`）自 **2026-09-04 起停牌**，到请求窗口末端 2026-10-31
仍未复牌（32 行里 29 个停牌交易日，09-04..10-22）。停牌行形态：

```
date       open   high   close  preclose volume amount tradestatus pctChg isST
2026-09-03 2.4600 2.4600 2.4600 2.4600  191728479 ...  1           0.0000 1
2026-09-04 2.4600 2.4600 2.4600 2.4600  (空)      (空)  0           (空)   1
...
2026-10-22 2.4600 2.4600 2.4600 2.4600  (空)      (空)  0           (空)   1
```

- **`preclose` 不是空值，也不调整**：逐日恒等于最后成交价 2.46（= 2026-09-03 收盘）。
- 于是停牌日 `f = preclose(D)/close(D-1) = 1.000000`，`pctChg` 为空。
- 工程含义：停牌日的 f≡1 是"没交易"而非"没事件"，**不能作为"无除权"的证据**；
  若停牌期间发生除权，按这套形态 f 也不会体现（除权日通常顺延到复牌日）——
  **这一点本样本没有出现，属推断，未验证（§9）**。
- 交叉印证：PG 的 `qfq` 序列对 000016 也止于 2026-09-03（8,196 行），两个来源一致说明
  它确实一直没复牌——顺带说明**不能把"序列最后一行"当作"最新交易日"**。

### 6.2 长期停牌复牌首日：**未验证**

本轮唯一天然长停牌样本 000016 到窗口末仍未复牌，没有复牌首日行；其余停牌样本都在
PG 的 5 日窗口外。因此"长期停牌期间若发生除权，复牌首日 `preclose` 是否仍为参考价"
**本轮没有实测**，不做结论。可确定的是相邻事实：停牌期间 `preclose` 每天重复最后成交价；
复牌首日的 `preclose` 语义需要在有样本时单独验证（建议：找一只停牌跨越股权登记日、
且 `query_adjust_factor` 事件日落在停牌区间的票，比对复牌日 `preclose` 与停牌前收盘）。

### 6.3 新股上市首日：`preclose` = **发行价**，f 无定义

`sz.301569`（2026-10-15 上市）当天：`close=35.12`、`pctChg=401.7143%`。反解

```
preclose = 35.12 / (1 + 4.017143) = 6.9999998 ≈ 7.0000 元
```

**`preclose` 不是空值，也不是"昨收"（首日没有昨收），而是发行价。** 该值是整数 7.00，
`pctChg` 的 4 位小数把 preclose 钉到 ~1e-6 相对精度，不可能是巧合。
次日（2026-10-16）`pctChg=-28.3314%` 反解 `preclose = 35.12`，即首日收盘——第二天起才
恢复"preclose = 昨收"。

工程含义（很重要）：

1. `f = preclose(D)/close(D-1)` 在上市首日**无定义**（没有 D-1 行），结论与 issue 一致。
2. 但**不能用"`preclose` 是否为空"来判断首日**——有值，而且看着像正常前收。
   若实现里用"序列上一行 close"当 D-1，首日会算出 `35.12/7.00 = 5.017` 这种伪因子。
   必须按"该票序列的第一行"显式排除。
3. `pctChg` 首日是相对发行价的涨幅，这是交易所口径，不是"日收益"，做收益序列时要同样排除。

（`301569` 的 `query_adjust_factor` 未单独请求——12 次额度已满。新股在**有了首个分红事件后**
会进入因子表：2026-05-22 上市的 `001237` 出现在 2026-10-16 的 48 行事件表里，可作为佐证。）

### 6.5 重复行与脏字段

5 个因子样本合计 **41 个事件行**，其中 **3 行**与上一行累计因子完全相同（无价格调整）：

- 真实的除权事件只在**累计因子发生阶跃**的那一行（如 600519 的 06-30：`f_pre=0.984881`；
  07-03 的 `f_pre=1.000000`）。**按行数统计事件会把 41 行当成 41 个事件，本样本多算 3 个（41 行 vs 38 个真实阶跃，~7%）。**
- 600519 2023-06-30 的 `adjustFactor` 是下一次事件的因子（前视污染，§3.4）。

## 7. 结论：能否作交叉校验源

**能，但要按"事件表"用，不能按"因子真值"用。**

| 用途 | 可行性 | 依据 |
| --- | --- | --- |
| 校验"某日是否发生除权/分红" | **可以，且性价比最高** | `query_daily_adjust_factor(date)` 1 次/交易日拿全市场事件表；10-16 样本 45/45 命中、0 漏 |
| 校验"事件日期是否错位" | **可以** | `dividOperateDate` 来自交易所除权日，是独立信息；且能识别"登记日/除权日"重复行 |
| 校验"因子数值对不对" | **不行/无意义** | 因子由同一批两位小数价格递推，与 preclose 同源；688300 的 1.3000382 vs 精确 1.3 即证据 |
| 给停牌/首日/缺行标的补因子 | **可以** | 这些场景 preclose 没有"昨收"语义，因子表是唯一可用来源 |
| 长历史累积因子（回补 qfq） | **可以** | 窗口不变、单调、退市也保留；但精度与 preclose 同级（1e-4 量级） |

### `preclose` 推导的失效清单

1. **上市首日**：`preclose` = 发行价（301569 例：7.0000），不是昨收；f 无定义。
   不能靠"preclose 为空"识别，必须按"序列首行"排除；否则得到 `35.12/7.00 = 5.017` 的伪因子。
2. **停牌日**：`preclose` = 最后成交价，f≡1，`pctChg` 为空。停牌不是"无事件"；
   停牌期间若发生除权，f 推测也不会体现（未验证）。
3. **序列末端截断**：长期停牌/退市标的最后一行不是最新交易日（000016 止于 10-22，
   qfq 止于 09-03），用"最后一行"当基准会错。
4. **两位小数量化**：单日 f 分辨率 0.005/preclose（11 元票 4.4e-4、100 元票 5e-5）。
   **小于该量级的现金分红不可靠**——本样本事件比值最小 0.9333（000001 2024-06-14）、
   最靠近 1 的 0.9988（全市场 10-16），都还在可测范围，但再小就落进噪声。
   需要平台中位数（#141 §4.1）或因子表。
5. **无 D-1**：新股首日、退市后、窗口首行，f 均无定义。
6. **复牌首日（长停牌+期间除权）**：未验证（§6.2）。

### 因子表自身的失效清单

1. **数值不是真值**：由两位小数价格递推，10 送 3 这种精确比值会带 2.9e-5 偏差。
2. **重复行**：本样本 3/41 行无价格调整，按行计事件会多算 ~7%。
3. **`adjustFactor` 列有前视脏值**（600519 2023-06-30），只用 `fore`/`back` 比值。
4. **含 ETF**：10-16 的 48 行里 3 只不是 A 股个股；A 股日线口径不含它们。
5. **窗口首事件无前值**：`start_date` 会裁掉更早的事件，窗口内第一个事件算不出 f。
6. **`fore` 随新事件重锚**：绝对值不能跨日缓存，跨日只能用比值。
7. **客户端无读超时**：全市场一把抓曾挂死 >15 分钟（§1.3），必须外部兜底。

## 8. 若要落地（本次未改任何代码）

1. **每日事件对账**：每交易日 1 次 `query_daily_adjust_factor(date)`，把 `(code, dividOperateDate)`
   作为当日事件真值；再用当日 `preclose(D)/close(D-1)` 造"异常日集合"，
   对账召回/误报。成本 1 次/交易日，与本轮 48 行规模同量级。
2. **对账前先过滤**：只保留 `sh.6*` / `sz.0*` / `sz.3*`（与
   `baostock_adapter.py:62` 的 `_STOCK_PREFIXES` 一致），把 ETF 行单列。
3. **排除伪因子行**：首日（序列首行）、停牌日（`tradestatus=0`）、无 D-1 的窗口首行
   一律不进 f 序列；判定"停牌"用 `tradestatus`，不要用"`preclose` 是否为空"。
4. **数值口径统一**：交叉校验一律用 `f = back(prev)/back(cur)` 与 `f_pre` 的**比值比较**，
   容差取 `max(1e-6, 0.005/preclose)`；不要用 `fore` 绝对值、不要用 `adjustFactor`。
5. **请求节奏**：本轮只验证了**串行 + 1.5s 间隔**下 11 次成功、1 次挂起；
   每交易日 1~5 次的量级未做连续多日验证，放量前应先限定小样本试跑（AGENTS.md 纪律）。
6. **超时必须外部加**：baostock 客户端无 `settimeout`，落地代码需要在调用侧用
   子进程/线程 + 超时兜底（本轮用 `signal.alarm(90)` 验证有效）。
7. **事件去重**：同一 `(code, backAdjustFactor)` 连续出现的行只保留首个；或在入库前用
   `f == 1` 丢弃。
